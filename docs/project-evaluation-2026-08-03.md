## 第一部分：项目现状总结

### 项目定位（一句话）

yunying 是一个**远程 Linux 主机操作平台**，为 AI Agent（MCP 协议）和人类（CLI PTY 透传）提供统一的远程终端访问、文件传输、端口转发和操作审计能力——把终端会话从人类界面变成可编程资源。

### 三、安全与合规

| 维度 | 现状 | 评级 |
|------|------|:----:|
| 认证 | API Key（SHA-256 哈希存储）+ Bridge Token + TLS 1.3，Token 常数时间比较；API Key/Bridge Token 均支持轮换与过期（rotate 后旧凭证 24h 宽限自动失效） | ⭐⭐⭐⭐ |
| 授权 | **0.9.1 Group RBAC**：组级隔离、超管/受限分级、`agent add` 强制显式指定权限 | ⭐⭐⭐⭐（0.9.0 前为 ⭐⭐） |
| 审计 | SQLite 结构化（66 种 AuditAction）+ bridge 端 asciinema v2 录制 + chattr +a 防篡改 + CLI 回放 | ⭐⭐⭐⭐ |

**评价**：0.9.1 的 Group RBAC 是从「单租户工具」迈向「多团队平台」的关键一步，安全面显著收窄。与 vssh/Ephyr 的差距集中在**哈希链审计**和**临时证书/策略引擎**两点。

## 第五部分：结论与建议

### 总体判断

**33 天做到这个完成度是罕见的高效率**：架构（Central Server + QUIC + 双通道）在 MCP 生态中保持领先，0.9.1 的 Group RBAC 补上了多租户这块关键短板，工程纪律（clippy 零警告、文档同步）持续在线。但**迭代速度与质量保障的剪刀差正在扩大**——这是当前最需要正视的问题。

### 优先级建议

| 优先级 | 事项 | 理由 |
|:------:|------|------|
| **P0** | 为 Group RBAC 鉴权路径补测试 | 安全关键代码零测试，是 0.9.1 最大的隐患 |
| **P0** | tools/ 核心工具（exec/send_keys/capture_pane/tunnel）单测 | 67 个工具的业务逻辑是回归风险集中区 |
| **P1** | 哈希链审计（参考 Ephyr/vssh） | 竞品对比中反复被点名的差距，实现成本不高 |
| **P1** | 命令级策略引擎（参考 Shuttle 4 级规则） | 生产环境准入的常见要求 |
| **P2** | CI 门禁回归远端（PR 级 fmt/clippy/test） | 单人 + 本地检查的组合在引入第二贡献者后会失效 |
| **P2** | 统一部署路径（install-bridge.sh 对齐 /usr/local/bin） | 已知不一致，趁早消除 |
| **P3** | CLI session 管理子命令、QUIC TCP 回退 | 体验与兼容性补强 |
